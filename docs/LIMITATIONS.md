# Limitations and evidence boundaries

- The six public examples are synthetic masks and a manually authored protocol. They establish engineering behavior only. No real-video model accuracy, latency, egress percentage, shadow agreement or successful deployment of Glimmer is claimed.
- Meta account access was verified by live Spark text/two-image and SAM image calls using a generated illustration. SAM returned two candidates, not a verified object identity. Voice returned a timestamped turn for synthetic computer-spoken audio. Physical recordings, native video calls and end-to-end real protocol validation remain pending; mocked transports still cover other adapter paths.
- Single camera, fixed tabletop, one protocol per job; 2 fps, at most 180 sampled frames (90 seconds). Fast actions between samples can be missed. Webcam streaming is not implemented.
- Geometry can establish visible contact or placement. It cannot prove liquid transfer, concentration, volume, mixing, sterility, correct cap tightness or hidden actions. This is a non-medical demonstration, not a lab safety system.
- Bbox containment is a coarse geometric approximation; touching thresholds depend on camera resolution. Model confidence is not calibrated. Occluded or ambiguous instances remain unknown.
- Image-keyframe SAM calls do not maintain stable IDs for visually identical objects. Multiple matches produce unknown evidence. Colored props and distinct prompts are required by this adapter. Native-video tracking is exercised by an opt-in spike, not used in the production observer yet.
- Absence/count predicates require complete scene coverage. Live SAM keyframes do not establish coverage, so they cannot confidently certify these predicates. A compiler may propose unusable predicates; validation must reject or repair them.
- All eligible cuts and adjacent inter-group swaps are evaluated. The final-step cut cannot establish a later transition, so its result is explicitly ineligible and finish remains uncertain. Video cuts may retain lasting effects of actions, making a control invalid; failed controls are not hidden.
- Dwell is time since observable activation, including waiting when a step has no preconditions. Define meaningful preconditions or generous dwell bounds for independent steps.
- Rules do not accept model-only completion. Human review is needed for unknown evidence; a confident LLM opinion cannot fill missing pixels.
- The selected configuration is API-only with Spark advisory/shadow reviews. Glimmer is optional; its Modal deployment is prepared and unexecuted. The GPU image, weight access, cold start, vision and latency still need live verification. Modal is cloud infrastructure, not on-device inference.
- Request and estimated-cost reservations are application guards, not a guarantee against provider charges. Set provider-side controls separately. SAM default call caps may reject long multi-object recordings; increase them deliberately after measuring cost.
- Local files and SQLite target a trusted single-instance deployment. The separately hosted Supabase workspace adds email/password authentication, owner isolation and private recording storage. The Python inference API now independently verifies Supabase bearer tokens and owner-scopes jobs, media and reports. Hosted jobs and private archives use Supabase. It still has no durable distributed task queue: an in-progress worker restart is surfaced as an interrupted job, not automatically retried paid work.
- Audit verification checks event consistency against a root. Replacing both the chain and root defeats local verification; provenance and external anchoring matter. It does not make the physical observations trustworthy.
- Real dev/test recordings must be independently labelled and frozen. Small samples and correlated events limit any performance conclusion.

- Supabase uploads stage recordings; they do not trigger analysis. Email confirmation requires the configured production redirect and working email delivery. The owner reported successful real signup and email confirmation on Oct 27; browser regression tests mock Auth HTTP. Other mail providers/volume remain unverified. Default provider mail quotas apply.
- A saved snapshot is user-supplied data and is not a certification of real model output. Account ownership does not establish the physical truth of a run.
- Storage uploads and metadata cannot be atomic across services; failed metadata writes attempt file cleanup, but interrupted requests can leave private orphan files.

- Synthetic sample replay, sample protocol inspection and browser chain verification are public and work from bundled static assets without keys, Supabase or a backend. Private uploads, saved runs, library access and paid analysis still require verified accounts. Frontend sample controls are a UX boundary; private data and paid operations are protected separately by RLS and API token verification. Public API exceptions match only six known sample IDs and explicit methods/paths, never arbitrary job prefixes.
- Sample API throttling is an in-memory, single-worker rolling limit of 30 requests/minute per socket IP with at most 4096 recent client entries. It resets on restart, applies to all sample-route callers, and is not coordinated across workers or applied to static assets. Forwarded headers are not read by this limiter; deployment proxy trust must be configured correctly so the server supplies client IPs.
- A narrowly scoped SECURITY DEFINER reservation RPC is intentional: it locks a private global ledger and requires both a real user JWT and a backend-only random key. The security advisor flags this exposed definer boundary; direct ledger access is revoked and tested. Private ledger tables intentionally have RLS without client policies (deny all).

- T2 packs mask histories losslessly and caps the internal decoded-raster cache at 8 MiB. The <200 MB regression covers 180 × 8 masks at 1024×768 plus mask metadata/cache, not peak process RSS or a guarantee that every workload fits a free worker. Caller-held arrays, OpenCV temporaries, two expert histories, JSON and concurrent jobs add memory. Decoded masks are read-only snapshots.
- Complex browser display contours are approximate: at most 256 points per object, using an initial 1.5 px approximation tolerance (increased only if a contour cannot fit) and preferring largest-area components. Wire metadata discloses tolerance and truncation. Tiny components may not be drawn; predicates and saved evidence overlays still use exact masks. Simple synthetic sample outlines are unchanged.

- T3 detailed native-video tooling reports parser frame indices, mask-ID recurrence, response diagnostics and usage, but has not been run for this change. Recurring IDs are not proof of physical identity; the documented guarantee excludes full occlusion and exit/re-entry. A provider request-byte maximum was not found in the checked docs; the spike's 10 MiB and 30-second caps are local precautions. Production native-video tracking and frame-based budgets remain pending observations.

## T4 local batch boundaries

The batch tool uses the local durable SQLite reservation ledger and rejects `CLOUD_JOBS=true`; it does not silently bypass hosted RPC budgeting. The optional cumulative cap is enforced before each Meta HTTP request by narrowing the current job's existing per-run reservation cap to the remaining batch allowance. Failed HTTP attempts and retries remain reserved. A single-output-folder lock prevents competing batch processes from racing its allowance. These are conservative cost reservations, not a guarantee about provider bills or exact actual spend. Unknown-priced remote open-model endpoints are rejected when a cumulative cap is requested; loopback open tiers and API-only mode are supported. Provider-side billing controls remain separate.

Interrupted/failed videos are not published as completed prediction JSONs. Cache hits can avoid repeat segmentation, but retries may still need advisory calls. Existing prediction SHA/protocol/split matches avoid new calls. Actual real-video batch quality, throughput and latency remain unmeasured.
