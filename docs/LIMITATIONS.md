# Limitations and evidence boundaries

- The homepage hero is an illustration, and the three product previews are screenshots of the animated sample workspace, not physical-procedure recordings. The Learn view keeps machine-readable completion rules behind expandable details; simplifying these labels does not change validation or step decisions.
- The six public examples are synthetic masks and a manually authored protocol. They establish engineering behavior only. They do not establish real-video accuracy. The separate private October 31 diagnostic measured provider-call latency and egress, but did not establish completed-step shadow agreement or a successful self-hosted Glimmer deployment.
- Meta account access was verified by live Spark text/two-image and SAM image calls using a generated illustration. SAM returned two candidates, not a verified object identity. Voice returned a timestamped turn for synthetic computer-spoken audio. Later photographic/native controls and the private October 31 website diagnostic are recorded in the API notes. End-to-end real protocol validation remains pending; mocked transports cover other adapter paths.
- Single camera, fixed tabletop, one protocol per job; 2 fps, at most 180 sampled frames (90 seconds). Fast actions between samples can be missed. Webcam streaming is not implemented.
- Geometry can establish visible contact or placement. It cannot prove liquid transfer, concentration, volume, mixing, sterility, correct cap tightness or hidden actions. This is a non-medical demonstration, not a lab safety system.
- Bbox containment is a coarse geometric approximation; touching thresholds depend on camera resolution. Model confidence is not calibrated. Occluded or ambiguous instances remain unknown.
- Native-video identity routing is implemented with conservative fixed bindings and synthetic parser tests. Two explicitly authorized synthetic video calls returned no parseable masks, so live native tracking/identity quality is unverified. Missing output frames and later identity ambiguity can retire a prompt group, reducing recall. The image fallback still cannot maintain stable identities for identical-looking props; multiple candidates stay unknown.
- Absence/count predicates require complete scene coverage. Live SAM keyframes do not establish coverage, so they cannot confidently certify these predicates. A compiler may propose unusable predicates; validation must reject or repair them.
- All eligible cuts and adjacent inter-group swaps are evaluated. The final-step cut cannot establish a later transition, so its result is explicitly ineligible and finish remains uncertain. Video cuts may retain lasting effects of actions, making a control invalid; failed controls are not hidden.
- Dwell is time since observable activation, including waiting when a step has no preconditions. Define meaningful preconditions or generous dwell bounds for independent steps.
- Rules do not accept model-only completion. Human review is needed for unknown evidence; a confident LLM opinion cannot fill missing pixels.
- The selected configuration is API-only with Spark advisory/shadow reviews. Glimmer is optional; its Modal deployment is prepared and unexecuted. The GPU image, weight access, cold start, vision and latency still need live verification. Modal is cloud infrastructure, not on-device inference.
- Request and estimated-cost reservations are application guards, not a guarantee against provider charges. Set provider-side controls separately. SAM default call caps may reject long multi-object recordings; increase them deliberately after measuring cost.
- Local files and SQLite target a trusted single-instance deployment. The separately hosted Supabase workspace adds email/password authentication, owner isolation and private recording storage. The Python inference API now independently verifies Supabase bearer tokens and owner-scopes jobs, media and reports. Hosted jobs and private archives use Supabase. It still has no durable distributed task queue: an in-progress worker restart is surfaced as an interrupted job, not automatically retried paid work.
- Audit verification checks event consistency against a root. Replacing both the chain and root defeats local verification; provenance and external anchoring matter. It does not make the physical observations trustworthy.
- Real dev/test recordings must be independently labelled and frozen. Small samples and correlated events limit any performance conclusion.

- Supabase uploads stage recordings; they do not trigger analysis. Email confirmation requires the configured production redirect and working email delivery. The owner reported successful real signup and email confirmation on Oct 27; browser regression tests mock Auth HTTP. Other mail providers/volume remain unverified. Default provider mail quotas apply.
- A saved snapshot is user-supplied data and is not a certification of real model output. Account ownership does not establish the physical truth of a run.
- Storage uploads and metadata cannot be atomic across services; failed metadata writes attempt file cleanup, but interrupted requests can leave private orphan files.

- Synthetic sample replay, sample protocol inspection and browser chain verification are public and work from bundled static assets without keys, Supabase or a backend. Private uploads, saved runs, library access and paid analysis still require verified accounts. Frontend sample controls are a UX boundary; private data and paid operations are protected separately by RLS and API token verification. Public API exceptions match only six known sample IDs and explicit methods/paths, never arbitrary job prefixes.
- Sample API throttling is an in-memory, single-worker rolling limit of 30 requests/minute per socket IP with at most 4096 recent client entries. It resets on restart, applies to all sample-route callers, and is not coordinated across workers or applied to static assets. Forwarded headers are not read by this limiter; deployment proxy trust must be configured correctly so the server supplies client IPs.
- A narrowly scoped SECURITY DEFINER reservation RPC is intentional: it locks a private global ledger and requires both a real user JWT and a backend-only random key. The security advisor flags this exposed definer boundary; direct ledger access is revoked and tested. Private ledger tables intentionally have RLS without client policies (deny all).

- T2 packs mask histories losslessly and caps the internal decoded-raster cache at 8 MiB. The <200 MB regression covers 180 × 8 masks at 1024×768 plus mask metadata/cache, not peak process RSS or a guarantee that every workload fits a free worker. Caller-held arrays, OpenCV temporaries, two expert histories, JSON and concurrent jobs add memory. Decoded masks are read-only snapshots.
- Complex browser display contours are approximate: at most 256 points per object, using an initial 1.5 px approximation tolerance (increased only if a contour cannot fit) and preferring largest-area components. Wire metadata discloses tolerance and truncation. Tiny components may not be drawn; predicates and saved evidence overlays still use exact masks. Simple synthetic sample outlines are unchanged.

- T3 detailed native-video tooling reports parser frame indices, mask-ID recurrence, response diagnostics and usage, and was run twice on synthetic clips with no parseable masks. Recurring IDs are not proof of physical identity; the documented guarantee excludes full occlusion and exit/re-entry. The general inline-file maximum is documented as 50,000,000 bytes, while a separate SAM JSON-body maximum remains unverified; the spike's 10 MiB and 30-second caps are local precautions. Production native-video handling and frame-based budgets are implemented, but real mask/identity and physical-procedure validation remain pending.

## T4 local batch boundaries

The batch tool uses the local durable SQLite reservation ledger and rejects `CLOUD_JOBS=true`; it does not silently bypass hosted RPC budgeting. The optional cumulative cap is enforced before each Meta HTTP request by narrowing the current job's existing per-run reservation cap to the remaining batch allowance. Failed HTTP attempts and retries remain reserved. A single-output-folder lock prevents competing batch processes from racing its allowance. These are conservative cost reservations, not a guarantee about provider bills or exact actual spend. Unknown-priced remote open-model endpoints are rejected when a cumulative cap is requested; loopback open tiers and API-only mode are supported. Provider-side billing controls remain separate.

Interrupted/failed videos are not published as completed prediction JSONs. Cache hits can avoid repeat segmentation, but retries may still need advisory calls. Existing prediction SHA/protocol/split matches avoid new calls. Actual real-video batch quality, throughput and latency remain unmeasured.

## T5 advisory and repair limits

The partner endpoint configuration is implemented and mocked transport/image-format checks pass, but event-alias access, image quality, usage, cost and latency remain unmeasured. Open-tier cost logs can be unknown; cloud accounting includes attempted remote image transmissions. Setting a display label does not prove deployment or model identity. No open-weight bonus eligibility is claimed without actual provider evidence. Shadow agreement now includes separate escalation opinions and should not be compared directly with older single-opinion metrics. Selective repair cannot fix missing visual evidence; protocols with unresolved checks remain unverified.

- The two detailed native calls measured 3,556 ms/50 billed frames/$0.010 estimate and 4,902 ms/80 billed frames/$0.016 estimate on synthetic clips. Both produced no parseable mask records. A later authorized three-second photographic diagnostic returned masks (see API notes); physical procedure tracking remains unverified.
- Image mode is the default pending real procedure footage. Local and hosted caps are deliberately 3,000 image calls, 6,000 native billed frames, $8/job and $10/day. Two90-second seven-object image passes reserve $6.30; advisory/compile calls also count against the cost ceiling. These are reservations, not guaranteed bills.
- Video fallback is limited to documented size failures and an explicit image mode. A generic unsupported/corrupt-video 400 has no verified stable SAM-specific subtype in the checked docs and is not automatically treated as a retriable format error. Full occlusion, entry/re-entry, sparse outputs and ambiguous IDs stay unknown.

- Narration-derived step boundaries are English heuristic proposals with 0.5-second padding, not observed action boundaries. Repeated, ambiguous or unmatched narration needs manual timing. Every range requires explicit video review before validation.
- Active recovery is bounded to one refinement plan (up to three schema attempts) and one SAM image re-query per job. It may fill only one missing mask; a unique model mask is not physical identity proof. Rules replay before any completion changes. Recovery diagnostics are outside the event-chain root.

- T6 proposes evenly spaced timing ranges when narration cannot identify a boundary. These are explicitly suggested, not observed timings, and require manual video review and confirmation. Plain narration is limited to4,000 characters and spans the full teaching video; it does not establish per-step timing. All-(0,1) placeholders and ranges outside the actual recording are rejected before paid validation. Browser integrity checks cover event/chain/root consistency, not all metrics, camera authenticity or physical correctness. T7 public real-footage replay has not started.


## October 31 real-video diagnostic

A licensed 13-second rope clip completed the private website pipeline, including replay, overlays, HTML download and chain verification. Its generated protocol was unverified and zero of five steps completed; advisory replies did not override unknown rule evidence. Image tracking required 182 requests and more than 16 minutes before base tracking finished. A native single-concept control returned masks, but the full native batch stopped at its advisory cap without exporting a prediction. These diagnostics establish integration behavior, not knot correctness, procedure accuracy, generalization or a submission-ready real sample. See [measured observations](meta_api_notes.md#real-video-website-diagnostic-outcome--october-31-2026).

Step-scoped advisory prompts and start/middle/end review frames reduce irrelevant context but cannot guarantee a truthful model opinion or recover unseen actions. Compiler guidance against ambiguous parts is not a segmentation capability check; a generated protocol still requires human review and all validation checks. Older saved reports retain their original hashed events; display wording changes do not retroactively repair their protocols or decisions.

Image requests use bounded concurrency (three by default, configurable1–4). This can reduce waiting for independent requests but provider rate limits, Supabase reservation latency and object count still dominate long recordings. The one-frame live comparison in the API notes is not an end-to-end speed guarantee. ETA describes the current stage using its observed pace; cache hits, retries, later stages and repairs can change the total duration. Progress is private worker-local metadata, survives only while that worker is available and is excluded from audit integrity claims.
