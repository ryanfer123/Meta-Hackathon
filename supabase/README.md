Live project: `Apprentice`, ref `ntuuztideqsdvuiiohlh`, ap-south-1, in ryanfer123's Org. The owner confirmed the quoted $0/month project before creation. Usage/plan changes can affect billing.

Apply `migrations/` in timestamp order to another Supabase project with the CLI or migrations connector. The migration filenames were generated by Supabase CLI 2.122.0. Configure the frontend with the project URL and a publishable key; never a service role key.

Auth settings: email/password, production Site URL `https://apprentice-meta.onrender.com/`, redirect allowlist `https://apprentice-meta.onrender.com/**`. These production settings were checked in the dashboard after reload. For local account confirmation, explicitly allow your own localhost origin; production does not allow arbitrary redirects.

## Data contract

- `protocol_records`: protocol definition, name, owner and provenance.
- `run_records`: complete run snapshot and evidence chain root, linked to a protocol with a composite owner foreign key.
- `recordings`: private file metadata, expert/held-out/novice role, staged analysis status.
- `recordings` Storage bucket: private, 50 MB limit, MP4/MOV, owner UUID folder prefix.
- `save_run_snapshot(snapshot)`: validates required fields, atomically saves protocol and run. No partial protocol if the run insert fails.
- `delete_run_snapshot(run_uuid)`: deletes the owner's run and its unused protocol in one transaction.

Every table has RLS. Authenticated users can access their own records only; anonymous database access is revoked. Invoker RPCs preserve policies and are executable only by authenticated users. Storage SELECT/INSERT/DELETE checks the owner folder; no public bucket or anonymous upload policy exists.

They cover owner visibility, peer read/update/delete denial, owner spoof denial, private storage isolation, anonymous denial, snapshot validation, failed-save rollback and paired deletion. Run in a new empty/test project; the count assertions assume an otherwise empty fixture account.

The later server-authorized budget functions intentionally use SECURITY DEFINER, and deny-all private-table RLS produces informational notices; these boundaries are documented and tested. Browser cloud interaction tests mock HTTP to check UI behavior without sending email or writing production user content. The owner confirmed successful signup and email confirmation; other mail providers and volume remain unverified. Model inference is a separate Python service and is not provisioned by these migrations.

## Hosted analysis additions

`analysis_jobs` persists owner-scoped job status/results; private `analysis-artifacts` ZIP archives preserve the minimal files needed to reopen results or resume protocol validation after worker restarts. One active job per account is enforced in Postgres. Clients can only access their own rows/folders.

`private.model_budget_config` holds a SHA-256 digest of a backend-only random key; `private.model_reservations` is inaccessible to browser roles. The reservation RPC intentionally runs as a definer to lock this global ledger, but requires both a user JWT and the separate backend key. No service-role key is used. Its advisor warning is intentional and reviewed; deny-all private-table RLS produces informational notices. `tests/hosted_analysis.sql` verifies wrong-key rejection, run limits, ledger isolation and peer-job denial, with all fixtures rolled back.

## Native-video budgeting

Migration `20261028163318_native_video_budgets.sql` adds billed-frame reservations, configurable trusted-server limits and a UTC-day accounting halt. The defaulted reservation arguments preserve existing four-argument callers; access still requires both the authenticated owner and backend-only server key. Native requests do not consume the image-call counter. The default hosted limits remain 2,000 billed frames per job, $2 per run and $5 per UTC day; local defaults are configured separately.

`reconcile_sam_budget` records unexpected extra billed frames/cost and halts new reservations globally for the UTC day. The browser cannot invoke it without the backend key. Both public definer functions deliberately lock the same private config row to serialize checks. A failed reconciliation also leaves a local worker halt; it does not assert that an unreachable remote write succeeded. Reservations and failed attempts are never refunded.

`tests/native_video_budgets.sql` passed against the live project: secret rejection, legacy calls, frame/image/daily caps, overrun accounting/day halt and private ledger isolation. Its disposable fixtures and temporary config changes were fully rolled back; it sent no model calls and did not delete existing reservations.
